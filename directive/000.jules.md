#### File 4: `headless_runner.py`

Simulate the compute and VRAM footprint of a 48-frame video diffusion pass (Wan 2.2 model tier):

* Accepts CLI arguments:
* `--model-path`: string (path to downloaded weights)
* `--frames`: int (default: 48)
* `--output`: string (path to write output MP4 plate)


* Logic:
1. Print `[PYTORCH] Initializing VRAM hydration...`
2. Measure elapsed time to allocate ~20 GB FP16 tensor in GPU memory (`torch.randn((1024, 1024, 5000), dtype=torch.float16, device='cuda')`). Call `torch.cuda.synchronize()`.
3. Emit stdout token: `VRAM_HYDRATION_MS:<integer_milliseconds>`.
4. Loop over `range(frames)` performing batched matrix multiplication (`torch.matmul`) with `torch.cuda.synchronize()` on every iteration to keep tensor cores pinned at 100%.
5. Write dummy bytes to `--output` representing the encoded video.
6. Gracefully catch `torch.cuda.OutOfMemoryError`, print `FATAL: CUDA_OOM_DETECTED`, and exit with code `137`.



#### File 5: `benchmarks/gate0Arbitrator.ts`

* OOM Failures: Green $0/10$, Yellow $1/10$, Red $\ge 2/10$


* Correlated Trend Analysis:
* If Yellow count is 1 and Red count is 0: Check if mechanically linked metrics (Ingress and Cost) are within 5% of their Yellow thresholds. If so, populate `correlated_trend_warnings`.

#### File 6: `harness.ts`

The Node.js container coordinator:

* Read environment variables: `R2_ENDPOINT_URL`, `R2_BUCKET`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `CHECKPOINT_KEY` (default: `checkpoints/wan2.2_i2v_14b.safetensors`), `RUNPOD_HOURLY_RATE` (default: `0.74`).
* Generate UUID for `RUN_ID`.
* Ensure `/tmp/models` and `/tmp/renders` directories exist.
* Phase 1 (Ingress):
* Execute `s5cmd` using `child_process.spawn()` with arguments:
`--endpoint-url ${R2_ENDPOINT_URL} sync --concurrency 64 --part-size 50 s3://${R2_BUCKET}/${CHECKPOINT_KEY} /tmp/models/`
* Measure elapsed time using `process.hrtime.bigint()`.


* Phase 2 & 3 (VRAM & Tensor Inference):
* Execute `python3 /app/headless_runner.py --model-path /tmp/models/... --frames 48 --output /tmp/renders/test_plate.mp4`.
* Parse stdout to extract `VRAM_HYDRATION_MS`.
* Measure compute phase duration.


* Phase 4 (Egress):
* Execute `s5cmd cp /tmp/renders/test_plate.mp4 s3://${R2_BUCKET}/outputs/gate0_${RUN_ID}.mp4`.


* Compilation & Output:
* Calculate active runtime burn cost: `totalSeconds * (hourlyRate / 3600.0)`.
* Evaluate result via `evaluateGate0()`.
* Write `/tmp/gate0_telemetry_${RUN_ID}.json`.
* Exit with code `0` on Green, `1` on Yellow, `2` on Red.
